# 产品宪章

> 受外部项目总控管理，Codex 不得自行修改产品原则。

## 项目身份

- 中文名称：BOSS直聘 AI 岗位雷达
- 内部英文名称：`boss-job-radar`
- 仓库：`MuHai12345/boss-job-radar`
- 属性：个人求职辅助工具

## 用户背景与求职范围

当前用户是 2023 届毕业生，正在社招场景中转行。当前搜索城市固定为上海，主要寻找电商运营入门岗位。

核心方向包括：

- 电商运营助理
- 天猫运营助理
- 淘宝运营助理
- 京东运营助理
- 店铺运营助理
- 初级电商运营
- 电商运营专员
- 商品运营助理

类目运营、平台运营等只作为补充方向，不能取代核心方向。

## 要解决的问题

项目帮助用户在本人正常使用 BOSS直聘 的过程中：

- 尽可能全面地发现可能相关的岗位；
- 保存岗位原始 BOSS 链接和完整 JD；
- 结合完整 JD 判断真实工作内容，识别名为运营但实际职责偏离的“伪运营”；
- 区分经验硬门槛、经验优先和表述矛盾，而不是只依赖平台经验标签；
- 分别记录招聘者活跃度、岗位新鲜度和链接可用状态；
- 分析岗位作为转行入口的成长价值；
- 给出风险提示和面试追问方向；
- 保留全部岗位，供用户本人查看、判断和决定是否投递。

## 高召回原则与最终选择权

本项目优先避免漏掉潜在机会，不以传统简历相似度作为核心判断。岗位判断必须阅读完整 JD，不能只凭标题、单个关键词或 BOSS 经验标签下结论。

低分、疑似伪运营、经验可能不匹配、招聘状态较差或信息不完整的岗位，可以被降级、标记风险或降低优先级，但不得因为分析结果而被静默删除或隐藏。

最终是否查看和投递，由用户本人决定。系统只提供记录、解释和辅助判断，不替用户作最终选择。

## 关键判断维度

- **岗位真实性质**：结合完整 JD 判断是否属于真实电商运营、混合岗位、伪运营或信息不足。
- **经验门槛**：区分明确最低经验、软性偏好、无经验要求、矛盾描述和模糊描述。
- **招聘者活跃度**：作为当前机会优先级的重要信号；无法可靠取得时必须显示未知。
- **岗位新鲜度**：岗位发布时间与程序观察时间必须分开；发布时间无法可靠取得时必须显示未知。
- **成长性**：关注岗位能否提供运营基本功、平台实操、数据分析、商品与活动运营等转行成长价值。

## 隐私、安全与行为边界

- 不自动投递，不自动打招呼，不自动聊天。
- 不要求、获取、导出或保存用户的 Cookie、Session、密码和验证码。
- 不调用或逆向 BOSS 私有 API。
- 不绕过验证码，不伪装浏览器指纹，不实现反风控。
- 不后台无人值守抓取或浏览。
- 第一阶段只考虑用户当前页面已经展示的 DOM 内容。
- 最终投递动作必须由用户本人完成。

## 成功标准

项目在遵守上述边界的前提下，应逐步做到：

- 提高上海电商运营入门岗位的发现覆盖面；
- 可追溯地保留原始链接、完整 JD 和观察时间；
- 对岗位性质、入门可行性、经验门槛、岗位状态和成长性给出分轴、可解释的判断；
- 未知信息明确标注未知，不用推测冒充事实；
- 所有岗位均可被用户查看和人工决策；
- 用户能够依据风险、机会优先级和面试追问信息更有效地进行人工求职。

这些标准只定义项目方向，不表示当前阶段已经实现。

## 明确非目标

- 代替用户作出最终投递决定；
- 自动投递、自动聊天或自动打招呼；
- 建设独立爬虫或后台无人值守采集系统；
- 调用 BOSS 私有 API 或规避平台安全机制；
- 请求或管理登录凭证、Cookie、Session 和验证码；
- 以单一总分、简历相似度或单个关键词决定岗位去留；
- 静默隐藏低分、疑似不匹配或信息不完整的岗位。
