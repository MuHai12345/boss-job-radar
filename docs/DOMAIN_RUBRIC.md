# 领域规则骨架

本文定义后续岗位分析使用的状态语义，不实现规则引擎，也不把任何状态映射为岗位的自动去留决定。

## 岗位性质

| 状态 | 含义 |
| --- | --- |
| `genuine_ecommerce_operations` | 完整 JD 显示核心职责主要属于真实电商运营工作，例如商品、店铺、活动、数据或平台运营等。具体判定规则需后续批准。 |
| `mixed_role` | JD 同时包含实质电商运营职责和占比不可忽略的其他职责，无法合理归为纯运营岗位。 |
| `pseudo_operations` | “运营”名称与实际核心职责明显不一致，主体工作更接近销售、客服、地推、直播出镜或其他非目标方向。必须基于上下文判断。 |
| `unclear` | JD 缺失、信息不足、描述过于笼统或相互冲突，不能可靠判断岗位性质。 |

## 入门可行性

| 状态 | 含义 |
| --- | --- |
| `suitable` | 现有信息显示岗位适合作为目标用户的电商运营入门机会。 |
| `worth_trying` | 存在部分门槛或不确定性，但仍值得用户进一步查看、沟通或人工判断。 |
| `hard_mismatch` | 完整 JD 存在明确且关键的硬性要求，与当前用户背景形成难以弥补的直接不匹配。该状态不等于删除岗位。 |
| `unclear` | 信息不足或相互矛盾，无法可靠判断入门可行性。 |

## 经验门槛

| 状态 | 含义 |
| --- | --- |
| `none` | JD 没有提出相关经验要求，或明确接受无经验候选人。 |
| `soft_preference` | 经验被描述为优先、加分或偏好，而非明确的最低硬门槛。 |
| `hard_minimum` | JD 明确规定最低年限或不可替代的相关经验条件。 |
| `contradictory` | 标题、平台标签、JD 不同部分之间的经验要求相互冲突。 |
| `ambiguous` | 描述含糊，无法确定经验是硬门槛还是偏好。 |

## 岗位状态

| 状态 | 含义 |
| --- | --- |
| `active` | 有可靠的当前证据表明岗位仍可正常查看，且存在近期招聘活动信号。具体证据标准由后续规则定义。 |
| `possibly_stale` | 岗位仍可能存在，但招聘者活跃度、发布时间或观察信号提示机会可能已陈旧。 |
| `unavailable` | 有可靠证据表明岗位链接或职位当前不可用。 |
| `unknown` | 缺少足够、可靠或当前的信息，无法判断岗位状态。 |

## 用户审核状态

| 状态 | 含义 |
| --- | --- |
| `new` | 已发现但用户尚未开始人工审核。 |
| `reviewing` | 用户正在查看或评估岗位。 |
| `shortlisted` | 用户已将岗位列为重点候选，但尚不代表已经投递。 |
| `not_interested` | 用户人工决定当前不感兴趣。 |
| `applied_manually` | 用户本人已手动完成投递。系统不得自动设置此状态来冒充人工投递。 |
| `archived` | 用户将岗位归档以保留记录，岗位仍不得从历史中静默消失。 |

## 判断原则

- 单个关键词不能直接决定岗位性质；后续判断必须结合完整 JD 上下文。
- 平台经验标签不能代替对 JD 中经验措辞的分析。
- 信息不足时使用 `unclear`、`ambiguous` 或 `unknown`。
- 不得为了得到确定答案而猜测，也不得用一个时间字段推断另一个时间字段。
- 各状态轴分别保存，不以单一总分覆盖差异。
- 低优先级、风险较高或信息不明的岗位仍应保留，最终选择权属于用户。
