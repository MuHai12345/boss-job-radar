# 阶段路线

本路线只描述计划顺序。未来阶段均未完成、未批准、未验收；是否进入下一阶段由外部网页版 ChatGPT 决定。

## Phase 0：项目基线

- **阶段目标**：建立项目文档、目录结构、治理基线、双角色协作规则和长期仓库记忆。
- **进入条件**：项目仓库可用，外部项目总控给出 Phase 0 明确任务。
- **主要工作范围**：产品宪章、架构基线、领域规则骨架、数据字典、路线图、项目状态、ADR 和工作日志。
- **明确非目标**：任何浏览器扩展、后端、数据库、AI 分析、审核界面或真实页面采集代码。
- **退出条件**：规定文件存在且一致，完成适用的文档验证，真实 commit 等待外部独立审阅。
- **用户人工验证**：需要；外部审阅者检查 GitHub 中的 commit，用户不需要登录 BOSS 进行页面验证。

## Phase 1：浏览器扩展和脱敏 fixture 解析

- **阶段目标**：建立最小 MV3 扩展与脱敏 fixture 解析能力，为真实页面验证准备可检查的被动采集原型。
- **进入条件**：Phase 0 经外部审阅通过，外部项目总控批准 Phase 1 的技术方案和任务。
- **主要工作范围**：扩展最小结构、只读 DOM 解析边界、脱敏 fixture、解析测试和字段缺失处理。
- **明确非目标**：真实 BOSS 页面结论、私有 API、自动浏览/翻页/点击、后端、SQLite、LLM、自动投递。
- **退出条件**：fixture 解析满足经批准的测试要求，扩展可供下一阶段人工验证，结果经外部审阅。
- **用户人工验证**：需要；用户需确认扩展安装与基本行为，但真实 BOSS 页面验证属于 Phase 2。

## Phase 2：真实 BOSS 页面人工验证

- **阶段目标**：在用户本人正常登录和浏览的前提下，验证当前页面 DOM 中目标字段的真实可得性、变化和缺失情况。
- **进入条件**：Phase 1 经外部审阅通过，用户同意在本机进行明确范围的人工验证。
- **主要工作范围**：人工打开页面、扩展被动读取已展示 DOM、脱敏记录结构差异、验证字段和失败模式。
- **明确非目标**：保存账号凭证、导出 Cookie/Session、私有 API、自动翻页、批量点击、无人值守采集、后端和分析能力。
- **退出条件**：形成可复核的脱敏验证记录，明确哪些字段可靠、条件性可得或不可得，并经外部审阅。
- **用户人工验证**：必须；页面访问和操作由用户本人完成，无法访问时不能以 fixture 冒充真实验证。

## Phase 3：本地服务和 SQLite

- **阶段目标**：在采集能力得到真实验证后，建立仅本机可访问的数据接收与持久化基线。
- **进入条件**：Phase 2 经外部审阅通过，数据边界和技术选型获得明确批准。
- **主要工作范围**：只绑定 `127.0.0.1` 的本地服务、SQLite schema、迁移、原始事实保存和基础测试。
- **明确非目标**：公网/局域网暴露、私有 API、自动浏览、LLM 分析、完整审核界面和自动投递。
- **退出条件**：本地服务边界、数据库持久化和恢复路径通过自动化测试及外部审阅。
- **用户人工验证**：需要；用户确认服务只在本机可达并验证基本数据保存流程。

## Phase 4：安全本地桥接、导入和去重

- **阶段目标**：安全连接扩展与本地服务，可靠导入观察记录并处理重复岗位。
- **进入条件**：Phase 3 经外部审阅通过，桥接协议、身份边界和去重规则获得批准。
- **主要工作范围**：本地桥接、输入校验、可追溯导入、幂等处理、去重策略和错误恢复。
- **明确非目标**：远程服务、凭证收集、后台采集、确定性业务评分、LLM 分析和自动投递。
- **退出条件**：重复导入、失败重试、字段缺失和安全边界通过测试及人工检查，结果经外部审阅。
- **用户人工验证**：需要；用户验证扩展到本地服务的受控导入流程。

## Phase 5：确定性规则分析

- **阶段目标**：基于已保存的完整 JD 和事实字段实现可解释、可版本化的多轴确定性分析。
- **进入条件**：Phase 4 经外部审阅通过，领域规则、样例和预期输出获得批准。
- **主要工作范围**：多轴状态规则、未知值传播、解释依据、风险标记、规则版本和测试样例。
- **明确非目标**：用单一总分删除岗位、LLM 推断、自动投递、以未知信息作确定结论。
- **退出条件**：经批准的规则样例和边界测试通过，任何岗位均未因分析结果静默消失，并经外部审阅。
- **用户人工验证**：需要；用户抽查规则解释与目标岗位的实际语义是否一致。

## Phase 6：结构化 LLM 分析

- **阶段目标**：在确定性事实和规则基础上增加结构化、可追溯的语义分析。
- **进入条件**：Phase 5 经外部审阅通过，模型使用、隐私、结构化输出和失败回退方案获得批准。
- **主要工作范围**：结构化输出 schema、提示词版本、完整 JD 上下文、结果校验、失败回退和成本/隐私控制。
- **明确非目标**：让模型替用户投递、用模型输出覆盖原始事实、猜测缺失平台字段、静默过滤岗位。
- **退出条件**：脱敏评测集、结构校验、未知值与失败回退达到批准标准，并经外部审阅。
- **用户人工验证**：需要；用户抽查解释、风险和面试追问的可用性。

## Phase 7：本地岗位审核界面

- **阶段目标**：提供本地界面，让用户查看全部岗位、原始证据、多轴分析并管理人工审核状态。
- **进入条件**：Phase 6 经外部审阅通过，界面范围、交互和数据展示规则获得批准。
- **主要工作范围**：岗位列表与详情、原始链接、完整 JD、未知状态展示、筛选排序、用户审核状态和人工投递记录。
- **明确非目标**：自动投递、自动聊天、自动打招呼、静默隐藏低分岗位或把筛选结果当作删除。
- **退出条件**：核心人工审核流程、可访问性、数据一致性和不丢岗位约束通过测试与外部审阅。
- **用户人工验证**：必须；用户完成代表性岗位的查看、筛选、标记和手动决策流程。

## Phase 8：搜索覆盖统计和稳定性增强

- **阶段目标**：衡量搜索覆盖和系统稳定性，改善长期个人使用中的可观察性与恢复能力。
- **进入条件**：Phase 7 经外部审阅通过，覆盖指标和稳定性目标获得批准。
- **主要工作范围**：搜索运行统计、覆盖趋势、重复率、缺失率、错误诊断、备份恢复和性能稳定性。
- **明确非目标**：承诺平台全量覆盖、规避平台限制、无人值守抓取、自动投递或扩大隐私数据范围。
- **退出条件**：批准的指标可解释、故障可诊断、恢复流程经验证，并由外部审阅者作出阶段结论。
- **用户人工验证**：需要；用户确认统计含义、长期使用体验和恢复流程符合预期。
